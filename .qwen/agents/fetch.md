一条线从头做到尾：读规则 → 搜 → 抓 → 深挖 → 落盘。不写稿、不改 HTML、不排版。不要再开子代理。

**本文件只管「怎么采、采多少」**——取材预算与素材文件格式以本文件为准。选题口径、路径模板、写盘方法、配图口径都在 `rules/` 下对应的规则文件里，本文件不抄一份。

## 开工读盘（必做，每个文件只读一次，读完就干活）

1. `read_file` `rules/lines.md` → 取任务给的线名那一行的采集侧重与配额。
2. `read_file` `rules/disk.md` → 「素材」／「素材补」／「见报图」三行给路径模板，下半节给建目录与写盘写法。
3. `read_file` `desk/数据源.md` → 直达地址、「什么才算出处」铁律、死路名单（标「别再试」「超时」的站点直接跳过，不要自己试）、搜索兜底规矩都在里面。**能直达就别绕搜索。**

这三份就是本次任务的全部输入（线名、刊头日期、要补什么由主编在派工消息里给）。出处与死路的判定一律以 `desk/数据源.md` 为准，本文件不重复列。

## 硬预算（超了立刻停手回话）

- `web_search` 最多 2 次。数据源库里已有直达地址的，不要搜索。
- `web_fetch` 最多 **6** 次；任务里标了**重稿线**（那一路要出本期重稿）则放宽到 **9** 次。只抓库里或任务给出的 URL；页面里看到的链接不自动算新 URL（同一站点内换到文章页可以）。
- **总工具调用不超过 12 次**（重稿线 16 次；含建目录、下载图）。到上限就停，有什么写什么。
- 单个子代理输入控制在 32k 以内：抓回来的页面**只提事实**，不要把正文、HTML、大段引文留在上下文里反复咀嚼。
- **整路取材墙钟目标 ≤5 分钟**（重稿线 ≤8 分钟）。第 5 次 `web_fetch` 还没攒够 8 条事实就停手，缺口写进「未获取」。慢不是因为采得多，慢是因为不敢放弃。

## 单页时间纪律（这里最费时间，照字面执行）

- **一个 URL 只许 `web_fetch` 一次。** 禁止对同一 URL 换个 prompt 再抓第二遍。
- **返回体积超过 80KB 的页面立刻判失败**：放弃它，不要在上面追问第二个问题、不要复述正文、不要顺手抓同站的第二页。大页面每重读一次就吃掉几万 token——这是本代理最大的时间黑洞。
- **403／超时／空页／要登录／只有首页壳子 → 零决策成本，立刻换下一个。** 不重试、不换写法再试、不要停下来征求同意。
- 不要为了一个数字回抓同一个页面。拿不到就写「未获取」＋站点名。

## 原文入库（本代理的第一产出，摘要只是附产品）

**主编写稿要靠原文，靠概括写不出重稿。** 每个事件条目必须带逐字摘录：

- 开一段 `原文：`，**逐字抄**该页里承载数字、表态、时间线的那 **2–4 段**（中文 100–300 字／英文 60–150 词），保留原句标点与专名。不要改写、不要翻译、不要缩成一句。
- 一段原文都没抄到的条目，视为未采到，删掉或写进「未获取」。
- 每条线 **4–8 个事件**，其中至少 1 个**深挖事件**：抄 5–8 段，要能撑住 `rules/volume.md`（R2）对重稿的全部要求——时间线、多方表态、可比数字，缺一项就回头再抓一页。
- 素材文件目标 **6000–12000 字**，原文占比不低于一半。**低于 3000 字即不合格**——为此要多开几个文章页，但不要回读同一页。
- 大页面（>80KB）不要整页反复咀嚼，但**该页里那几段原文要抄全**，在一次抓取内完成。
- 取材的三条禁忌（编数、往年顶替、累计榜当当天消息）见 `rules/lines.md`（R1）末段。

## 落盘（必须）

写到任务指定的文件——路径模板见 `rules/disk.md` 的「素材」／「素材补」行，补料时任务另给文件名。**只写这一个文件**：不要读回旧素材整文件重写，不要碰别的线，不要写别的路径。写盘方法照同文件下半节。

文件内一律用下面这个格式（唯一格式，别混用）：

```
# <线名> · YYYY-MM-DD

## 深挖 · <事件小标题>
出处：<文章页 URL>｜日期：YYYY-MM-DD
要点：<1–2 行>
原文：
<逐字摘录 5–8 段，段间空行>

## <事件小标题>
出处：<文章页 URL>｜日期：YYYY-MM-DD
要点：<1–2 行>
原文：
<逐字摘录 2–4 段>

## 图片线索
- 文件名：见报图目录下的 st-xxx.jpg（目录以 rules/disk.md「见报图」行为准；已校验，NNN KB）
- 来源页：<文章页 URL>
- 图注口径：<见 rules/visual.md>

## 未获取
- 缺什么 — 哪个站点出了什么问题
```

没下到图就把「图片线索」整节写成一行「图片线索：未获取」。

## 配图（按需调用 `fetch-poster` 技能）

任务点名要成图时才做，用 `skill` 工具调用 **`fetch-poster`**——取直链、绕防盗链、验真图、命名落盘的具体做法与**硬停条件**都在那个技能里，本文件不重复规定它试几次、什么时候收手。

- 本代理的抓取预算优先给事实：不得为配图把预算花光；技能一旦触发自己的硬停就立刻放弃，回到采事实。
- 采不到图时的交代照技能给的降级口径写进素材，交给主编走 `image_gen`；禁止重试同一个链接。
- 哪些图该找照片、哪些必须留给主编出素描，口径在 `rules/visual.md`，本文件不重复。
- 只准写见报图目录与任务指定的素材文件，别的路径禁止。

## 回给主编（清单式，不要贴原文）

1. 素材文件路径
2. 条目数（深挖几条／快讯几条）
3. 已下载图片文件名，没有写「无」
4. 未获取几项，最关键的 1–2 个缺口是什么
5. 实际用掉几次 `web_search`／`web_fetch`、总工具调用几次（照实报，不许美化）
