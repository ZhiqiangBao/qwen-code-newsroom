# 主编规程

## 选题与证据

1. 确认刊头日期，再调 `mcp__desk__plan`。读来源的状态与候选链接。超时或降级时让该线改查固定来源或做定向搜索。正常无新稿的来源可以跳过。
2. 五路取材用 `fetch`。任务给工作区绝对路径、采访线、日期与待补问题。收回材料后打开入选候选的原始出处。日期区分事件发生、公告和报道。两篇转述沿用同一原始出处时登记同一个来源链标识。
3. 先决定读者最需要知道的变化，再定头条和一篇分析。逐条写事实与证据的对应关系。未核的标题、快讯线索、失败原因留在素材区。确定能刊登的稿件后，将合规 JSON 交给 `mcp__desk__select`。[证据表格式](evidence.md)

## 写稿与核对

1. `mcp__desk__copy_lineup(date, from_materials=true)` 按入选证据表写稿。同一时刻只运行一项写稿请求。一篇稿出错时只修该稿对应事实或句子，再重写对应 ID。
2. 请 `copy-check` 对照证据表和原件读标题、导语、正文、引语与图表数据。高风险稿必须核到独立来源和当事方回应。主编精读头条、分析及高风险稿，处理未解决证据问题。证据不足时移除该稿或降低体裁，更新证据表并重新生成受影响的稿件。
3. 交 `makeup` 分版。用实际长度留出标题、副标题和图件空间，页面只放可刊发的稿件。图片绑定到具体稿件，图表使用可核数据与清楚的单位、截止时间。没有合适图件时使用纯文字版。

## 输出候选

1. `mcp__desk__compose` 生成日期版。 `mcp__desk__prepare` 返回候选页路径及其指纹。发现正文漏源、内部文字或资源丢失时按具体错误回到对应编辑环节。
2. `mcp__desk__review(date)` 量尺全部候选版。修正后重新生成候选。让具备看图能力的校对人员打开实际候选页与导出图，查看首屏、文章阅读顺序、图注和窄屏布局。硬伤阻断本期。
3. 把候选路径、指纹及待核事项交给主编。只有主编确认事实、文体和桌面与手机阅读效果后，才使用 README 的发行命令。候选更新后以新指纹为准。
