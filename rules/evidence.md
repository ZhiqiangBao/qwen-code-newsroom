# 入选稿件证据表

主编核过原件和报道后，按下面的结构提交整期证据表。 `mcp__desk__select` 接收日期与 JSON 字符串，返回入选 ID 和分析稿 ID。

- 顶层填写 `date` 和 `stories`。日期为刊头日期，事件须在此前七天内。旧资料可以作为背景来源，发布日期须早于刊头日期。
- 每篇写 `id`、`line`、`kind`、`title`、`event_date` 与 `risk`。体裁取 `普通`、`快讯`、`深挖`、`分析`、`评论`。风险取 `normal` 或 `high`。有取材底稿时可写相对路径 `source`。
- `sources` 中每个来源写 `id`、`name`、`url`、`published_at`、`kind` 和 `origin`。来源类型取 `primary`、`independent` 或 `secondary`。引用同一原件的转述共享 `origin`，即使媒体名不同。
- `facts` 的每项填写 `text` 和 `refs`。每条引用写 `source`（来源 ID）、`locator`（如披露编号、章节、表格行、视频时间）和短 `excerpt`。数字将单位、统计周期和时点写在事实中；自行计算注明公式和原始数字。正文会生成来源链接，定位和摘录留在证据表。
- 一期选一篇 `分析`，另写 `question`、`baseline`、`limit`。填读者的具体问题、可核的比较基准和结论的边界，并为比较双方各登记事实。
- 要在读者版呈现数据表时附 `table`。填写 `caption`、`columns` 和 `rows`。每行用 `cells` 填对应列的文字，用从 1 开始的 `fact` 编号标明该行来自哪项已核事实。窄屏可在表格内横向移动。
- `high` 用于重大指控等需要提高门槛的稿件，至少登记两条独立证据链并填写 `response`。回应或回应状态也应有来源和事实条目。头条须有一手来源，或有两条独立的直接报道。

只有标题可以继续查证。找到全文后再引用正文事实。重要但未披露的口径，可以写成经原件核对的具体限度。
